# 6. Admin panel and app secrets

The admin panel lives at `/admin` inside the same site. Admin accounts are created from the terminal; there's no public sign-up page.

Admin logins are separate from customer accounts. Customers sign up through Supabase Auth; admins use their own login stored in this app's database. A customer account can never open `/admin`.

Two secrets are generated by you, not by any platform:

| Variable | What it does | If it leaks |
|---|---|---|
| `ADMIN_SESSION_SECRET` | Signs the admin login cookie | Someone could forge an admin login. Change it and redeploy; that logs everyone out |
| `CRON_SECRET` | Lets only Vercel's scheduler run the cleanup job | Someone could trigger the cleanup early (it only deletes week-old unpaid drafts). Change it |

Generate each with:

```bash
openssl rand -base64 48
```

---

## Testing

In `.env.local`:

```env
ADMIN_SESSION_SECRET=any-string-at-least-32-characters-long-xx
CRON_SECRET=anything
```

Create your admin (against whatever `DIRECT_URL` points at, here the Docker database):

```bash
npm run admin:create -- you@example.com "a long password"
```

Then sign in at http://localhost:3000/admin.

To test the cleanup job by hand:

```bash
curl -H "Authorization: Bearer anything" http://localhost:3000/api/cron/cleanup
# {"deleted":0}  (drafts younger than 7 days are kept)
```
